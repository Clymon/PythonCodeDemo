REFERENCE SCENARIO — wrong-answer review

These are the proposed teaching rules carried forward from the terminal trial.
They are a reference answer for the instructor role, not claims from a real
learner interview. During the exercise, clarify or revise them explicitly.

1. A candidate's latest valid answer is incorrect, considering quiz and review.
2. Unanswered questions are excluded. Each candidate appears once in bank order.
3. A correct review answer removes that question; a wrong one keeps it.
4. Review never changes the original first-quiz-attempt score.
5. Invalid answers are rejected without writing an attempt.
6. Review returns only this browser profile's questions, never another learner's.
7. Starting a review round snapshots the candidates. Show each once in that round;
   correcting it does not erase its feedback before the learner reads it.
8. The next review round uses current candidates; provide an empty state and a
   clear completion state when the last mistake is corrected.
9. SQLite progress survives browser refresh and Python restart with the same cookie.
10. Normal quiz, lesson reading and completion must keep working.

HTTP boundary: GET /api/review returns candidate questions and a count without
answer keys. POST /api/answers accepts mode=review only for a current candidate.
Reject a review answer for an unanswered/already-correct question with 409.

Deliver one vertical slice first: one wrong quiz answer becomes a visible review
question, can be corrected through Python, persists and leaves the score intact.
Then extend to empty, mixed, repeated, invalid, corrected and restarted cases.
