DEVELOPMENT DECISIONS IN THE REVIEW EXAMPLE

The wish “find lessons I want to revisit” leaves the selection rule open.
A student choosing a lesson and a program selecting it after an incorrect
answer would produce different review lists. Ask who makes that choice.

When a student chooses the lesson, agree how to tell that the feature works.
One useful check is to leave the lesson, refresh, open the review list and
return to the same lesson. The student's completion and score should still
follow the existing rules.

Use the agreed behavior to choose the first complete ticket. A working button
alone leaves the learner without a route back. A saved list alone gives the
learner no way to put a lesson there. Show one end-to-end action before
extending the feature.

A browser check shows what the learner can operate. An API test can check
persistence and isolation. Review what actually ran and what remains open.
