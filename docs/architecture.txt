ONE ANSWER, THROUGH THE WHOLE SYSTEM

Browser page (templates/index.html + static/app.css)
    Learner selects an option and presses Check answer.
        |
Browser behavior (static/app.js)
    fetch POST /api/answers {question_id, choice, mode}
        |
HTTP boundary (routes.py)
    Validate JSON, browser token, question and practice mode.
        |
Learning rules (quiz.py)
    Check the answer; preserve original score; select review candidates.
        |
Storage (db.py)
    Append an attempt in instance/learning-lab.sqlite.
        |
JSON response -> browser feedback, counters and next interaction.

Python serves both the frontend files and API. The frontend is HTML/CSS/JS;
Python runs on the server, not directly inside the browser. SQLite is a local
file, not an additional service. All assets are local; no Node build is needed.

API MAP
GET  /                       HTML shell
GET  /api/dashboard          safe lesson content and this profile's progress
POST /api/answers            check and persist a valid quiz/review answer
POST /api/lessons/<id>/complete  save or undo reading completion
GET  /api/review             latest-answer-wrong questions (reference version)

Question keys remain in server-side JSON. The ordinary dashboard and review
responses omit answer keys. Feedback explains an answer after submission.
Reading completion, original score and current review membership are different
concepts. A corrected review can reduce current mistakes while leaving 0/1 as
the original score. Tests should preserve that distinction.
