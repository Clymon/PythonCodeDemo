LMS STARTING PRODUCT — navigate when investigation needs it

app.py starts one local Flask process. learning_lab/__init__.py loads course content
and initializes storage. catalog.py is the shared reading interface over the course,
chapter and lesson hierarchy. routes.py exposes course/navigation/learning behavior.
quiz.py holds existing scoring rules; db.py stores learner progress and attempts.
The English interface is templates/index.html and static/app.js/app.css. Local
resources need no CDN, build step or cloud account.

Trace a real teaching flow before proposing changes. The participant describes a
teaching purpose; the Agent investigates source facts and relevant checks, then
explains reusable capabilities, missing capabilities and meaningful consequences.

The catalog is loaded at startup. Existing learner records belong to an
anonymous browser profile. Inspect the actual code and tests to learn which
records exist before proposing new review behavior.

GET /api/courses lists the public catalog. GET /api/dashboard returns enrolled
courses and their records for this learner. Course detail exposes a syllabus
before enrollment and full lesson content after enrollment. The learner joins
with POST /api/courses/<id>/enroll. Valid answer and completion writes now
require enrollment. All writes use the existing JSON and CSRF checks.

POST /api/courses/<id>/lessons/<id>/open records a position in the enrollment
row. The open order increases for this learner across courses, allowing the
dashboard to select the last opened lesson even when requests happen within
one second. Existing completions and attempts are migrated at startup.
