LEARNING LAB — learn to direct an AI coding agent

The teacher demonstrates each activity, then each participant works independently.
Use the student branch. The webpage is the product you improve during the course.
The sample Python/Git/testing lessons are practice data, not this workshop's
curriculum. Your work is to make decisions, direct development and judge evidence.

1. ENVIRONMENT AND PRODUCT
   Clone student, install the recorded dependencies and run python app.py.
   Open the browser, read a lesson, answer a question and refresh.
   Human output: describe what the product already lets a learner do.
   Agent work: investigate files and explain relevant existing capabilities.

2. ONE SMALL DELEGATION
   Ask the agent to make the homepage greeting suit your class. Agree on the
   visible result and keep the change small. Observe its tool actions, inspect
   its summary/diff, refresh the browser and commit the verified change.
   Human output: accept or revise one observable result, with a reason.

3. DISCUSS A FEATURE — lab-discuss
   Use docs/client-brief.txt as the request. Ask the agent to use lab-discuss.
   Choose among the rules it identifies; ask what each option changes for learners.
   Save confirmed choices in workshop/decisions.txt using templates/decisions.txt.
   Human output: at least one reasoned choice, a boundary and a concrete example.

4. TURN DECISIONS INTO WORK — lab-plan
   Use lab-plan with the confirmed record. Review the proposed spec and small
   tasks: what works after each task, how can you check it, and what genuinely
   depends on another task? Revise before approving work.
   Human output: a confirmed spec and one ready, independently verifiable task.

5. IMPLEMENT ONE TASK — lab-implement
   Choose an approved task and use lab-implement for that task. Watch one behavior
   check fail for missing behavior, then pass after the smallest implementation.
   Try the actual page. Add the next behavior only after checking the first.
   Human output: a running result and a decision to accept, revise or continue.

6. CONTEXT AND CONTINUITY — lab-handoff when useful
   Distinguish durable project rules, on-demand Skills and current task records.
   Decide whether to continue, start fresh with saved artifacts or hand work to
   another task. In a fresh task, supply the handoff and ask it to restate the
   agreed rules and next action before editing.
   Human output: a next-task brief that preserves the important decisions.

7. REVIEW AND ACCEPT — lab-review
   Compare the implementation with the agreed examples. Run relevant tests,
   operate the browser and ask what remains unverified. Record evidence using
   templates/evidence.txt. Check a normal and a boundary case; test refresh/restart
   when the requirement includes persistence.
   Human output: a justified acceptance decision and a stated limitation.

Submit decisions, the spec/task, evidence and a brief demonstration.
Assessment rewards decisions, task boundaries and evidence. Source navigation,
manual Python coding, test count and a coverage target are not completion
requirements. See docs/assessment.txt.
