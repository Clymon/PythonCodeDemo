THREE-HOUR WORKSHOP — LLM, context and original Matt Skills
14:30–17:30; instructor demonstration followed by individual practice.

Learning outcome
Explain how an agent obtains project evidence, then turn a teaching need into
clear decisions and small verifiable tasks, choose an original Skill and judge
the delivered behavior. The sample lessons inside the app are product content.

14:30–14:55  1. Environment and working product (25 min)
WorkBuddy Code workspace, model/permissions, Git clone/branch/snapshot, prepared
Python startup and browser tour. Evidence: operate a working starting product.
Complete installation, sign-in and dependency preparation before class.

14:55–15:20  2. LLM, context and agent exploration (25 min)
Token generation (4), context/working range (4), harness/context categories (5),
project-overview question (5), deeper behavior question (7).
Use the colored context demonstration and docs/agent-exploration.txt. Observe
actual file/tool activity. This is read-only; a code edit is not the entry task.
Evidence: explain one claim and the project evidence the agent used to support it.
Smart zone/dumb zone is a metaphor, not a fixed percentage or a universal limit.

15:20–15:40  3. Discuss a teaching need (20 min)
The agent can investigate facts; humans decide unresolved behavior and scope.
Use original grill-me -> grilling. Evidence: confirmed choices and a concrete example.

15:40–15:55  4. Specification and complete tickets (15 min)
to-spec synthesizes the discussion. Demonstrate to-tickets for complete usable
slices and actual blockers; participants inspect and approve one actionable task.
Agree on public verification boundaries. Evidence: a spec and one ready ticket.

15:55–16:05  Break (10 min)

16:05–16:40  5. Implementation and feedback (35 min)
Use implement -> tdd / code-review. Observe a real missing-behavior check then a
passing check, inspect the running slice and the scope of the commit. Explain
git diff/staging/commit with this first real feature change. If already committed,
inspect git show HEAD instead of making a duplicate commit for the lesson.

16:40–16:55  6. Project rules and continuity (15 min)
Return to the introductory context model. Place stable rules, a loaded method,
shared vocabulary and current spec/tickets appropriately. Use handoff for another
teacher and check a fresh recipient's reconstruction before editing.

16:55–17:20  7. Review and acceptance (25 min)
Read the existing Standards/Spec findings and compare tests with actual browser
evidence. Reuse that review rather than restarting it just to fill a stage.
Check useful gaps and explain the limits of Python coverage. Decide accept/revise.

17:20–17:30  Demonstration and transfer (10 min)
Show a decision, a complete task, a running result and an acceptance reason.
Suggest a small improvement in a tool used in your own subject.

Total 180 minutes including the break. Require one genuinely verified usable
slice and a clear next action, not completion of every reference feature.
The installed-client T01 implementation/review trial took 36m13s; keep a separate
reference ready and explain concepts while the agent runs. No opening pretest,
mandatory pairing, compulsory greeting edit or random AI-failure demonstration.
Offline illustration: docs/interactive/llm-context-agent.html.
