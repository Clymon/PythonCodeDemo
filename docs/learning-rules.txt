LEARNING LAB — existing behavior for the LMS starting product

Courses contain ordered chapters; chapters contain lessons. IDs are stable and
unique. A lesson can contain ordinary text; code, resources and checks are optional.
One browser profile is an anonymous learner. Reading completion and valid attempts
are stored in SQLite. First valid quiz answers set the original score; retries do
not replace it. Invalid answers save no attempt. Reading completion awards no mark.
Course progress and scores include that course's current lessons/questions only.
Records survive refresh and server restart with the same browser cookie.

The student catalog is prepared content loaded from a local file at server startup.
It has no content-writing endpoint or teacher editor. That fact is for the Agent
to investigate when it matters; learners discuss its effects on teaching work.
Decisions for content maintenance remain open: first supported workflow, content
scope, preview/visibility, identity and learning-record compatibility. Explain any
change to an existing rule and get a deliberate decision. Instructor examples do
not select the participant's policy. This is a local workshop, not an institutional
account system. The main Teaching demo is explicitly a local reference view.
